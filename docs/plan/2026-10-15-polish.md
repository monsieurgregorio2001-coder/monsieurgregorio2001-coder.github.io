# Plan — Hub polish, October 2026

Status: proposed, awaiting owner sign-off
Owner: Garfield Greg Lim III
Author: Claude (session 2026-10-15)
Inputs: `docs/audits/2026-10-15-hub-audit.md`, ADRs 0004–0008

## Goal

Take the hub from "tasteful and safe" to "memorable and deep" without making it loud. A reviewer should land, feel the hero respond, see PaperLab as the lead, go one level deeper on any project, and leave with the impression of a practitioner who measures things.

Non-goals for this initiative: About photo / career arc / resume link (ADR 0008), a blog, a CMS, a framework migration, analytics.

## Principles

1. **The headline stays the star.** Every effect is tuned so the Fraunces headline is the first thing read.
2. **One idea per surface.** Hero = alive. Work = flagship + depth. About/Contact = unchanged in content, refined in craft.
3. **Numbers trace to commands.** No figure on the site without a reproducible source noted in the repo.
4. **Both themes, all three widths.** Nothing ships without screenshots at 390, 820, 1280 in light and dark.
5. **Reduced motion is first-class.** Every animation has a static equivalent that reads as intentional.

## Phases

Each phase is one branch, one PR, merged when its acceptance checks pass. Phases 1–2 can run in parallel; 3 depends on 2; 4 depends on 1–3; 5 runs throughout.

### Phase 0 — Repo foundation (this PR)

- `docs/` tree: README, audits, decisions, plan, TRACKER, CHANGELOG.
- `CLAUDE.md` at root: conventions for copy, numbers, screenshots, build.
- CI (`.github/workflows/check.yml`): html-validate, axe via Playwright on `/` in both themes, link check, and "build output matches committed HTML" once Phase 2 lands.

Accept when: CI green on the branch; docs render on GitHub.

### Phase 1 — Interactive hero (ADR 0005)

Files: `hero.js` (new), `style.css` (hero rules), `index.html` (canvas + decode spans).

1. Port the glyph field from the `Professionalism/portfolio` prototype into `hero.js`; replace its tokens with `--muted` / `--accent`; swap the font to JetBrains Mono 11 px on a 7×14 cell; read colours from computed CSS variables so both themes work from one atlas builder.
2. Clip the canvas to the hero section (not fixed to the viewport). The field fades to transparent in the bottom 20 % so the proof points sit on clean paper.
3. Headline decode: wrap each `<h1>` character in a `<span aria-hidden>` with the real text in an `aria-label` on the `<h1>`. On first paint, show scrambled glyphs; resolve left-to-right over ~1.1 s with a 40 ms stagger. Word hover: scramble and re-resolve that word once (debounced 600 ms).
4. Ripple ↔ headline: when a ripple front crosses a character's cell, scramble it for 300 ms. Implemented by reading character positions once on layout and comparing against ripple radius per frame.
5. Reduced motion: no canvas animation (one static frame), headline resolved, no hover scramble.
6. Performance: `requestAnimationFrame` loop with a visibility pause (`document.hidden`), density update every 3rd frame, ≤ 6 ripples, glyph atlas cached per theme. Target ≤ 4 ms/frame at 1440×900; measure with `performance.now()` deltas logged in dev only.
7. Contrast guard: glyphs under the headline bounding box capped at 15 % alpha.
8. Retire `Professionalism/portfolio/index.html` with a commit there pointing to this repo.

Accept when: axe 0 violations; frame time measured and recorded in TRACKER; screenshots at three widths × two themes committed to `docs/audits/shots/phase-1/`; reduced-motion screenshot included; owner approves the feel on their own machine.

### Phase 2 — Build script and featured PaperLab (ADR 0004, 0007)

Files: `scripts/build.mjs` (new), `index.html`, `main.js`, `style.css`, `projects.json`.

1. `build.mjs` reads `projects.json`, renders cards into `index.html` between markers, and renders the noscript list to link to case pages. Idempotent; CI diff-checks it.
2. `projects.json` gains `slug`, `featured: true|false`, `order`, and `screens[]` (for case pages, Phase 3).
3. Featured block for PaperLab at the top of Work: full-width, 12-column grid at ≥ 900 px with the screenshot spanning 7 and the text 5, headline set in `.display` size, three large proof numbers (19 tests · 58 KB · Lighthouse 96/100/100/100), one primary action "Open the demo", secondary "Read the case".
4. Remaining three cards keep the current layout but gain: 2× screenshot crops, a hover lift (`translateY(-2px)` + border tint to `--accent` at 30 %), image scale `1.02` on hover, staggered reveal (60 ms per card), and a "Read the case" link.
5. Re-shoot screenshots: extend `capture.mjs` with a `--crop` mode that captures a named region at `deviceScaleFactor: 2`, outputs 1600×1000 WebP + PNG. One hero crop per project. PNG fallbacks capped at 200 KB via `sharp` quality stepping.
6. `main.js` shrinks to reveal-on-scroll only.

Accept when: build is idempotent (`node scripts/build.mjs && git diff --exit-code`); page weight ≤ 450 KB first load; screenshots legible at card size (owner check); CI green.

### Phase 3 — Case-study pages (ADR 0006)

Files: `work/<slug>/index.html` ×4, `case.css`, `assets/shots/<slug>/*`, `assets/og/<slug>.png`, `sitemap.xml`.

1. Template first: write `work/paperlab/index.html` by hand against the ADR 0006 section order. Extract shared chrome (header, footer) into `build.mjs` partials so the four pages stay consistent.
2. Draft content for each page from the project repos: README, test files (for counts and what is tested), `package.json` (for stack), recent commits (for decisions). Every figure gets an HTML comment with its source (`<!-- src: npm test, 2026-10-14, 19 passing -->`).
3. Architecture diagram per page: inline SVG, ≤ 8 boxes, labels in Inter, strokes in `--rule`, highlights in `--accent`, `currentColor` so it adapts to theme. Drawn by hand, reviewed for legibility at 390 px.
4. Detail screenshots: 2–4 per project via `capture.mjs --crop`.
5. OG image per page from `assets/og-image.svg` with the title and proves line substituted; `og.mjs` loops over projects.
6. Sitemap lists the five URLs. Each case page has canonical, OG, Twitter tags, prev/next nav, and a "Back to work" link that returns to the right card (`/#work-<slug>`).
7. Owner review pass on every page before merge; corrections logged in TRACKER notes.

Accept when: four pages live; axe 0 on each in both themes; every number has a source comment; owner has signed off on content; Lighthouse ≥ 95 on each page (run locally with `npx lighthouse`, result pasted into TRACKER).

### Phase 4 — Craft pass

Files: `style.css`, `index.html`, `favicon.svg`.

1. "Now" line under the hero lead: one sentence, in `--muted`, sourced from `projects.json` (`now` field) so it is easy to update.
2. Proof points link: "12 MCP tools" → `#work-mindmap`, PaperLab figure → `#work-paperlab`.
3. Button and link states: hover tint, focus ring already present, active press (`scale(.98)`), all under 180 ms.
4. Tags become links to the case page section that mentions them, or are trimmed to three per card. (Decide during the pass; record in TRACKER.)
5. Favicon: a 2-glyph monogram in JetBrains Mono on `--accent`, SVG with `prefers-color-scheme` media so it flips with the theme.
6. Footer gains the five page links and a "Built without a framework" line that links to ADR 0001.
7. 404 page gets the hero field (static frame) so it feels like the same site.

Accept when: three-width × two-theme screenshots committed; axe 0; owner approves.

### Phase 5 — Verification and release (continuous)

- Each PR: CI green, screenshots attached, TRACKER updated, CHANGELOG entry.
- After Phase 3 merge: live checks the audit could not run (Pages headers, subpaths, OG previews on LinkedIn and X). Record in a new audit file.
- Final: re-run the full audit script; write `docs/audits/2026-11-xx-post-polish.md` with before/after numbers.

## Risks

- **Hero performance on low-end phones.** Mitigation: cap cell count at 6,000; drop the glow on touch; measure on a real Android if available.
- **Case page content accuracy.** Mitigation: source comments on every figure; owner sign-off gate.
- **Scope creep in Phase 4.** Mitigation: the list above is the whole list; anything else goes to TRACKER "Later".
- **Mac-only scripts.** Mitigation: scripts take `CHROME` from env and fall back to Playwright's bundled Chromium when present, so CI and the cloud session can run them.
